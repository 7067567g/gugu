# gugu 三模式架构（Work / Design / IDE 一壳三模式）

> 状态：M0 定稿（2026-10-12）。本文是三模式建设的**唯一权威架构文档**——
> 后续所有模式相关改动先对齐本文，改完回写本文。所有 file:line 基于
> `dev/gugu`（Hermes v2026.9.24 深 fork）当前代码。

## 1. 目标与总架构

```
┌─────────────────────────── Electron 壳（唯一）───────────────────────────┐
│  主进程：多窗能力现成（mainWindow / peer 实例窗 / HUD / secondary…）      │
│  渲染层：一壳 × $appMode × 三 UI 树                                       │
│                                                                         │
│   $appMode: 'work' | 'design' | 'ide'   （src/store/app-mode.ts 新增）   │
│     │ 切换副作用：navigate(模式路由) + applyLayoutPreset(模式预设)        │
│     ▼                                                                   │
│   ┌─ Work ──────┐  ┌─ Design ────────────┐  ┌─ IDE ─────────┐          │
│   │ 聊天会话布局 │  │ 画布居中 + 资产右pane │  │ chat+files 占位│          │
│   │ （现状默认） │  │ + 窄会话栏并存       │  │ （M1 后补深）  │          │
│   └─────────────┘  └─────────────────────┘  └───────────────┘          │
│   每模式独立布局持久化（layout-persistence 键泛化，见 §4.3）              │
├──────────────────────────── IPC / WS ───────────────────────────────────┤
│  后端（唯一 hermes serve 子进程）                                        │
│   ├─ tui_gateway JSON-RPC：会话/agent 语义（模式无关，共用）              │
│   ├─ /api/plugins/gugu-design/*：Design 文档/资产/任务（FastAPI 插件门）  │
│   └─ api-net 聚合网关（HTTPS）：chat / images / videos（登录=咕咕授权）   │
└──────────────────────────────────────────────────────────────────────────┘
```

核心原则（与用户确认）：
1. **模式 = UI 概念，不是后端隔离概念**——绝不用三 profile 承载（否决理由见 §2）。
2. **Design 不从零自研**——移植 dsh-design-mode（MIT，同栈 TS+Konva+React）成熟件。
3. **Work 与 Design 逻辑完全不同**——Design 有独立 UI 树/布局/工具栏，但共享会话内核
   （万镜一刻形态：对话窄栏 + 画布主区并存）。
4. **文档先行**——每个里程碑先改本文再动代码。

## 2. 决策记录（ADR）

### ADR-1：不用 profile 承载模式
探索结论（src/store/profile.ts:285-289、electron/backend-command.ts:18-21）：
一个 profile = 一个独立 `hermes serve` 子进程，切换 = 换 socket + 整窗 reload，
插件 API 需逐 profile 启用（web_server_dashboard.py:783-795 信任门）。
profile 语义是"另一个用户/另一台机器"，不是"同一个我的另一种工作界面"。

### ADR-2：移植 dsh-design-mode 而非自研画布
`refs/dsh-design-mode`（MIT）与桌面端同栈，其画布三件套经过真实产品验证：
- `packages/client/ui-design-mode/src/client/DesignCanvas.tsx`（504 行）：Konva
  Stage 手势全套——指针中心缩放、空格/中键平移、点选/框选、Transformer 缩放、
  评论锚点（point/rect/mask）、OTP 式评论编号。
- `packages/client/ui-design-mode/src/client/controller.ts`（1125 行）：
  `DesignSessionController`——Host 权威文档 + 浏览器乐观状态 + undo/redo 快照栈 +
  串行 mutation 队列（operationTail promise 链）+ asset objectURL 缓存 +
  composer context 芯片注册（懒解析）。
- `packages/client/ui-design-mode/src/client/DesignSurface.tsx`（1166 行）：
  二级面板——工具栏、上下文图像工具、评论/版本 inspector。
- `packages/design/design-mode/src/storage.ts`（~400 行）：服务端存储纪律——
  document.json 原子写（temp+rename, 0o600）、journal.ndjson 审计、
  MIME magic 嗅探、symlink/路径容器化防护、尺寸上限、版本图环检测。
- `packages/design/design-mode/src/index.ts`：宿主服务——per-session 串行队列
  （mutationTails/jobTails）、revision 乐观锁、operationId 幂等（recentOperationIds
  上限 100）、崩溃恢复（running→queued 于首次 read）、jobWaiters 广播 +
  AbortController 取消、凭证仅在 job 启动瞬间解析。

我此前的 `src/plugins/gugu-design/canvas.tsx` 是功能验证玩具版，M2 用移植版替换。

### ADR-3：万镜一刻/即梦补"我们没有的能力"
对标清单见 `docs/01-Design功能对标清单-v1.md`。模式化（M1）与画布移植（M2）之后，
按 M3（引导意图协议）→ M4（资产+芯片）→ M5（故事板+技能芯片）追赶。

### ADR-4：生成链路走 api-net，不走独立 provider key
Design 的图像/视频任务全部经 `hermes_cli/gugu_service.gateway_credentials()`
（model.base_url + ${ENV} key），与桌面登录同一份配置。网关已实现 OpenAI 兼容
`/v1/images`（native 模板转 DashScope multimodal-generation）与 `/v1/videos`
异步任务。浏览器/渲染层从不直连 provider。

## 4. M1 壳层设计（模式切换）

### 4.1 模式注册表 `src/app/modes.ts`（新）
```ts
export type AppMode = 'work' | 'design' | 'ide'
export interface ModeDef { id: AppMode; route: string; presetId: string; icon: string; labelKey: string }
export const APP_MODES: readonly ModeDef[] = [
  { id: 'work',   route: '/',        presetId: 'layout.work',   icon: 'comment-discussion', labelKey: 'mode.work' },
  { id: 'design', route: '/design',  presetId: 'layout.design', icon: 'layout',             labelKey: 'mode.design' },
  { id: 'ide',    route: '/ide',     presetId: 'layout.ide',    icon: 'code',               labelKey: 'mode.ide' },
]
```

### 4.2 `$appMode` 与切换器
- `src/store/app-mode.ts`（新）：nanostores atom + localStorage 持久化
  （键 `gugu.appMode.v1`）；`setAppMode(mode)` = 写 atom → `host.navigate(def.route)`
  → `applyLayoutPreset(def.presetId)`。
- 切换器位置（用户指定）：**侧栏顶部**，"收起侧边栏"按钮旁——挂
  `sidebar.profileGroup.header` 槽（routes.ts:141-158）或侧栏 header 区
  （src/app/chat/sidebar/index.tsx:1572-1700 渲染体的顶部）。
  组件 = SegmentedControl 三项（Work/设计/编程）。
- 冷启动：读持久化 mode → navigate 对应 route。

### 4.3 布局持久化泛化（唯一触碰核心文件的点）
`src/lib/layout-persistence.ts:72` 现为：advanced 裸键 / simple 加 `.simple` 后缀。
改为按 `${appMode}.${interfaceMode}` 表驱动前缀（work 保持裸键以兼容存量数据）。
**只改 keyFor 函数与 createLayoutPersistence 的 scope 参数，不动其余逻辑。**

### 4.4 Design 布局预设
注册 `layout.design`：workspace 居中（画布页）、assets 右 pane（M2 提供）、
sessions `resting:true`（可展开成窄栏，与画布并存——万镜形态）、terminal 收起。
Work/IDE 预设即当前默认树/微调。

## 5. M2 Design 应用层

### 5.1 前端（src/plugins/gugu-design/ 重构）
| 新文件 | 移植自 dsh-design-mode | 改造点 |
|---|---|---|
| `canvas.tsx` | client/DesignCanvas.tsx | 去 cordis：remote→ctx.rest；评论锚点保留 |

| `surface.tsx` | client/DesignSurface.tsx | slot 注入→workspace.pageHeader + panes 贡献 |
| `types.ts` | design/design-mode/src/types.ts | 基本原样（已是纯类型）|
| `activation.ts` | client/activation.ts | modeEnabled 挂到 gugu-design document |

### 5.2 后端（plugins/gugu-design/dashboard/plugin_api.py 升级）
- 存储纪律：document.json temp+rename 原子写、journal.ndjson、magic 校验、
  realpath 容器化（storage.ts 逐条平移，Python 实现）。
- 串行队列：`mutation_tails: dict[pid, asyncio.Future 链]`；job 队列同理。
- 幂等：operationId + recentOperationIds(≤100) + operationResults。
- 崩溃恢复：进程启动/首次 read 时 running→queued。
- 事件推送：`GET /events` WS（pluginSocket 门），替代 2s 轮询。
- 生成任务：图像同步/视频异步（现有实现保留），产物注册 asset+version。

### 5.3 会话并存
Design 模式下 sessions 侧栏 resting（可展开窄栏）；画布批注→composer 上下文芯片
（M4）→提交时物化进会话消息。会话即 Hermes session，agent 可被唤起处理画布任务。

## 6. 如何加第四种模式（操作手册）
1. `src/app/modes.ts` 加一行 ModeDef（route/presetId/icon/labelKey）。
2. 注册 ROUTES_AREA 整页（或复用现有页）。
3. 注册 `layouts` 预设（tree DSL，含需要的 pane 组合与 resting 项）。
4. 如需独立后端数据：新建 `plugins/gugu-<name>/dashboard/{manifest.json,plugin_api.py}`
   （/api/plugins/<name>/ 自动挂载）+ `src/plugins/gugu-<name>/` 前端。
5. i18n：`src/i18n/{zh,en}.ts` 加 mode 标签。
6. 更新本文 §1 架构图与 §3 表。
